# The safety tests: the tests that protect a shaker. Each must exist, must not
# be ignored, and must be compiled in the test build (tools/check_drive_path.py
# checks all three); CI runs them with every other test. A pull request that
# removes one, ignores one, or removes a line here says so in its title
# (docs/drive-path.md, "Weakening a protection").
#
# Format, one test per line, fields separated by spaces:
#
#   crate  file  test  kind  what it protects
#
# crate is the folder under crates/; file is the path inside it; test is the
# test function's name, or module::name when one file has two tests of that
# name. kind is one of:
#
#   drive-ceiling       the drive is held at or under its ceiling
#   drive-abort         a drive past its abort ends the run
#   stop-ramp           a stop ramps the drive down, never a step
#   abort-to-zero       an abort takes the drive to zero at once
#   run-thread-failure  a failure on a run thread ends in a stop, not a drive left playing
#   law-guard           a control law's bad, late or panicking answer is held and stops the run
#   envelope            a response outside its tolerance ends the run
#   kinematic           acceleration, velocity and displacement limits
#   divergence          a loop that grows instead of converging is stopped
#   overload            an input at the end of its range is caught
#   underrun            an output that runs dry ramps down and stops
#   dropped-controller  a run whose controller goes away ends in the safe stop
#   late-tick           a loop that falls behind real time is caught
#   watchdog            the raw-input abort limits on the loop thread
#   arm-gate            a run that cannot be driven safely is refused before it drives
#   checked-input       a value read from a file or the wire is checked before it reaches a run
#   authority           only the controller drives, and only through the control service
#   shutdown            a service or app that ends takes its run's controlled stop first
